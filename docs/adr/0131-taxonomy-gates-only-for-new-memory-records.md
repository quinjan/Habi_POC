# Taxonomy Gates Only For New Memory Records

A candidate creates a Taxonomy Gate only for a new unmatched Material, Service, or external Provider. Selecting an existing active Memory Record through a Memory-Aware Name inherits that record's current Resolved Category Path, displays the category as read-only, and creates neither a Taxonomy Gate nor a Taxonomy Decision; the candidate's aggregate Taxonomy Status treats that subject as accepted. Internal and Unknown Provider States continue to create no Provider Memory Record and therefore no Provider Taxonomy Gate.

To change taxonomy while an existing record is selected, the reviewer must first clear the corresponding Material, Service, or external Provider Memory-Aware Name. Clearing removes the Memory Record identity and returns that subject to a new-record state: its taxonomy restores GPT-5.5's original complete category suggestion as an editable pending gate, and the reviewer must repopulate the name before import. The original model suggestion is retained even while an existing match temporarily displays its inherited category, so reset and taxonomy history remain auditable. Selecting an existing option again restores its canonical name and read-only category and removes the new-record gate; entering unmatched free text retains the pending gate and requires explicit acceptance. Existing record reclassification remains a separate Project Memory action under ADR 0016.

For active new-record gates, the candidate-specific acceptance, draft, history, terminal-batch, and aggregate-status rules from ADR 0118 remain in force. This supersedes ADR 0118's requirement to create gates for subjects already linked to existing Memory Records and avoids audit entries that falsely imply a reviewer accepted an already-reviewed inherited category.
