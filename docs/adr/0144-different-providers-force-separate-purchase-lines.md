# Different Providers Force Separate Purchase Lines

A multi-concept Bundled Purchase Line requires one shared Provider identity and Provider State across every linked concept, or one shared Unknown Provider State for the complete bundle. When source evidence assigns different external Providers, or divides work between an external Provider and Internal crew, GPT-5.5 creates separate Purchase Lines by Provider even if the source states only one combined total. Each resulting line has a review-visible Unknown structured price unless the source allocates a price, and the exact combined-total wording becomes a grounded shared qualifier on every affected line.

For `Cement supplied by Wilcon and installation completed by our crew, combined project cost PHP 50,000`, Habi creates a Wilcon Material Purchase Line and an Internal Service Purchase Line rather than a bundle. This preserves the one-Provider Purchase Line model, prevents incorrect Provider Roles, and keeps Internal work from being promoted into an external Provider record. Shared headings and explicit anaphora may still establish that multiple links use the same Provider; mere proximity or Project Memory may not.
