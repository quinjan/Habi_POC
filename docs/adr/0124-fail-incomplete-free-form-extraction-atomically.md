# Fail Incomplete Free-Form Extraction Atomically

If any detected free-form Purchase Line candidate still fails source-grounding or semantic invariants after its permitted GPT-5.5 `xhigh` repair, or immediately when retries are disabled under ADR 0127, Habi will fail the entire Processing Job and create no partial Review Batch. This supersedes ADR 0092's keep-valid-and-drop-invalid behavior only for free-form Manual Source Entries because a partial batch could appear complete while silently omitting a purchasing fact; XLSX and other extraction paths retain their existing policies.

The user-facing Processing Job error must say that free-form extraction could not produce a complete grounded Review Batch, report how many detected Purchase Lines remained invalid after retry, and state explicitly that no candidates were saved. It should direct the reviewer to inspect the source and retry. Processing Job detail displays each affected exact source excerpt, its verified character range, and a plain-language validation reason so the reviewer can locate the failure without seeing raw model output. Compact operator diagnostics retain validation reason codes, affected locators, attempt count, pinned model, and reasoning effort without storing the raw model response under ADR 0094 or duplicating full source content in generic logs. A representative message is: `Free-form extraction could not produce a complete grounded Review Batch. 1 of 4 detected Purchase Lines remained invalid after retry, so no candidates were saved. Review the affected source text and try again.`
